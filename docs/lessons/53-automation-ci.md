# 53. CI/CD 与 GitHub Action

> 让自动化只做可验证、可回滚的检查。

所属部分：集成与自动化

## 你要学会什么

- 用一句话说清《CI/CD 与 GitHub Action》解决的问题。
- 判断什么时候应该使用这个能力，什么时候应该停止等待人工确认。
- 写出一条边界清楚、可执行、可验收的 Codex 提示词。
- 在任务结束后检查 diff、命令结果、截图或日志证据。

## 实战情景

你有一个写清楚验收标准的 Issue，希望 Codex 产出一个小范围 PR。

## 可复制提示词

```text
请围绕《CI/CD 与 GitHub Action》帮我完成一次实战练习。

目标：让自动化只做可验证、可回滚的检查。
范围：只使用当前练习项目，不处理生产环境、账号发布、密钥和未授权数据。
要求：先只读分析，再给最小执行方案，等我确认后再修改或运行命令。
输出：相关文件、执行步骤、验证方法、风险点和下一步建议。
```

## 操作步骤

1. 先准备一个无敏感信息的练习项目。
2. 把上面的提示词改成自己的真实任务。
3. 要求 Codex 先只读分析，确认范围后再执行。
4. 修改完成后看 diff，不接受无关重构。
5. 跑项目已有的验证命令；没有命令时，写清楚手动验收方式。
6. 把好用的提示词沉淀到 AGENTS.md、团队文档或自己的速查表。

## 验收清单

- [ ] 任务目标和修改范围写清楚。
- [ ] Codex 没有触碰密钥、账号、生产发布和未授权数据。
- [ ] 交付里有文件清单、验证结果和剩余风险。
- [ ] 如果涉及页面，已经检查移动端和桌面端。
- [ ] 如果涉及 PR，描述里包含问题、改动、验证和风险。

## 常见误区

- 只说“优化一下”，没有目标、范围和验收。
- 看到 Codex 输出很长就以为完成了，没有检查 diff。
- 为了让测试通过而删除断言、跳过测试或隐藏错误。
- 把本地路径、密钥、账号细节写进公开文档或截图。

## 下一步练习

完成这一课后，找一个真实但低风险的小任务，让 Codex 用同样格式输出：分析、方案、修改、验证、复盘。
