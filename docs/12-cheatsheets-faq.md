# 速查与 FAQ

## 常用提示词

### 只读扫描

```text
请只读扫描当前项目，列出技术栈、目录结构、启动命令、测试命令和风险点。不要修改文件。
```

### 陌生仓库接管

```text
请只读扫描当前仓库，不要修改文件。
输出项目用途、技术栈、入口文件、核心目录、启动命令、测试命令、风险边界和 3 个新手练习任务。
如果信息不足，请说明依据不足，不要编造。
```

### 小范围实现

```text
请只修改与这个任务直接相关的文件。完成后说明 diff、验证命令和剩余风险。
```

### 功能实现前置分析

```text
我要实现一个小功能：[写目标]。
允许修改：[写目录或文件]。
禁止修改：[写禁区]。
验收标准：[写测试、截图或用户行为]。
请先只读定位相关文件，输出最小实现方案、风险点和验证方法。等我确认后再修改。
```

### 修 Bug

```text
请修复这个 Bug。
用户看到的问题：[现象]
期望行为：[正确结果]
复现路径：[页面、按钮、设备、浏览器]
请先复现或说明无法复现，再定位最小原因，做最小修复，并给出回归验证。
```

### 补测试

```text
请为这个行为补测试：[行为]
要求先识别现有测试框架，不降低断言，不跳过失败测试，不为了通过测试而绕开业务逻辑。
完成后运行相关测试，并说明覆盖和未覆盖范围。
```

### PR Review

```text
请以代码审查方式检查当前改动。
先列 Findings，按严重程度排序。重点看行为回归、安全边界、无关改动、移动端问题和缺失测试。
每条问题给出文件、行号、影响和建议修复。最后再给简短总结。
```

### 前端验收

```text
请检查 390px、768px、1440px 三个宽度，确认没有横向溢出、文字遮挡、图片加载失败或 CTA 被挡住。
```

### 公开内容检查

```text
请扫描公开文件，确认没有密钥、非公开资料、账号细节、私密路径或不应公开的策略。
```

### 上线前检查

```text
请做上线前检查，只汇报结果，不执行发布。
检查构建、关键路由、390px/768px/1440px、图片视频、公开内容安全、CTA 和回滚路径。
输出 PASS / WARN / BLOCKED、问题、建议修复和人工确认项。
```

### 内容资产改写

```text
请把这次 Codex 实操整理成内容资产：
1. 中文教程大纲
2. 可复制提示词
3. 小红书卡片标题
4. 60 秒短视频脚本
5. GitHub README 更新建议
6. 人工审核清单

要求：不写内部研究对象，不暴露密钥、路径、账号和部署细节，文案自然引导读者找我学习。
```

## FAQ

### Codex 会不会直接替我做所有事？

不会，也不应该。Codex 适合执行可验证任务，不适合替代你的判断。

### 新手先学 CLI 还是 App？

我建议先学 App。理解项目、diff、多线程和本地预览后，再学 CLI 自动化。

### AGENTS.md 有必要吗？

非常有必要。它能让 Codex 每次进项目时都按同一套规则工作。

### Skills 什么时候学？

当你发现一个流程重复做三次以上，就可以考虑做成 Skill。

### 如何避免 AI 乱改？

任务写小、边界写清、先只读、再修改、最后验证。

### 为什么我总强调“情景”？

因为新手最容易卡在“我不知道该怎么问”。情景能把问题变成任务：谁遇到什么问题、希望得到什么结果、允许改哪里、怎么验收。Codex 最擅长执行这种边界清楚的任务。
