# 02. 用 Codex App 建立第一个工作区

我建议中文区新手优先从 Codex App 开始。原因很简单：你可以把本地仓库、浏览器预览、GitHub、Linear、设计工具和素材文件放在同一个工作流里。

## 第一次打开先做什么

1. 选择一个练习项目，不要包含生产密钥和客户数据。
2. 让 Codex 只读扫描项目结构。
3. 确认它能看到 README、配置文件、源码入口和测试命令。
4. 让它总结“这个项目是什么、怎么启动、怎么验证、哪里危险”。
5. 再开始写 `AGENTS.md`，不要直接给大任务。

## Local、Worktree、Cloud 怎么选

| 模式 | 我会怎么用 | 注意事项 |
| --- | --- | --- |
| Local | 日常主线开发和页面验收 | 改动前后都看 diff，重要任务先建分支 |
| Worktree | 多任务并行 | 每条线独立提交，避免互相污染 |
| Cloud | 远程 Issue 到 PR | 先确认仓库权限、密钥边界和 review 流程 |

## 我的桌面端工作流

```text
只读扫描项目
-> 写 AGENTS.md
-> 拆小任务
-> 执行修改
-> 跑构建/测试
-> 截图或证据验收
-> 提交 GitHub
-> 做成教程/卡片/视频素材
```

这个顺序看起来慢，但它会让你后面的每一次操作都更稳。

## 练习提示词

```text
请用只读方式扫描当前项目。
列出：项目目标、入口文件、启动命令、构建命令、测试命令、潜在风险。
然后提出 3 个适合新手练习的小任务。
本轮不要修改文件。
```

## 验收标准

- Codex 能说清楚项目入口。
- Codex 能说清楚启动和构建命令。
- 你已经知道哪些文件不能让它碰。
- 你有一份可以继续扩展的 `AGENTS.md`。
