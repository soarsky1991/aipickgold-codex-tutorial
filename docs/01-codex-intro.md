# 01. Codex 是什么

我是智辰老师。你可以先把 Codex 理解成一个会读项目、会改文件、会跑命令、会解释风险的 coding agent。

但真正有价值的地方，不是“AI 帮你写几行代码”，而是你能不能把它变成一套稳定工作流：

- 先读项目，再动手改。
- 先写边界，再给任务。
- 每次修改都有 diff、验证命令和风险说明。
- 把重复流程沉淀成 `AGENTS.md`、Skill、教程和发布包。

## 四种入口

| 入口 | 我建议你怎么用 | 适合场景 |
| --- | --- | --- |
| Codex App | 作为主工作台 | 本地项目、多线程、浏览器验收、素材和文档整理 |
| Codex CLI | 作为终端执行器 | 脚本化任务、远程机器、批量检查 |
| IDE / Extension | 作为局部助手 | 小范围编辑、补全、解释单个文件 |
| Web / Cloud | 作为远程任务入口 | Issue 到 PR、云端执行、团队协作 |

## 新手最容易踩的坑

- 一上来就让 Codex “直接实现”，结果上下文不够。
- 没有写清楚哪些文件不能碰。
- 没有让它跑构建或测试，就急着发布。
- 把账号、密钥、生产环境和私人素材直接暴露给 AI。
- 学完一篇教程没有留下模板、清单、仓库记录。

## 第一个 30 分钟练习

1. 找一个无敏感信息的小项目。
2. 让 Codex 只读扫描项目，并列出入口文件、启动命令、构建命令和风险。
3. 写一份最小 `AGENTS.md`。
4. 让 Codex 完成一个很小的改动，例如 README、文案或样式。
5. 要求它解释 diff，并跑一次构建或测试。
6. 把这次过程整理成一份学习笔记。

## 我希望你带走什么

Codex 不是许愿机。它更像一个需要你训练的项目合伙人。你给它边界、上下文和验收标准，它才会稳定地帮你做事。
