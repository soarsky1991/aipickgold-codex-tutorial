# 集成与自动化

自动化不是把人踢出去，而是把重复步骤交给系统，把关键判断留给人。

## 我常用的自动化层级

1. 本地命令：构建、测试、截图。
2. GitHub Action：CI、PR 检查、自动化修复。
3. Linear / Issue：任务入口和状态管理。
4. 发布包：把输出整理成可审查文件。
5. 人工确认：上线、发布、账号、付费动作。

## GitHub Action 思路

一个好的 Action 不应该只跑命令，还要产生证据：

- 哪个 commit。
- 跑了什么命令。
- 失败在哪里。
- 需要谁确认。

## 自动化提示词

```text
请把这个任务拆成自动化步骤：
1. 哪些可以脚本执行
2. 哪些必须人工确认
3. 哪些需要写入日志
4. 哪些不能公开
```

## 什么时候不要自动化

- 你自己还没有稳定做过三次。
- 输出无法验证。
- 失败会产生真实损失。
- 需要外部账号最终确认。

先可重复，再自动化。
