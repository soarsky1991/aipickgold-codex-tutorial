# 真实项目工作流

我学 Codex 的方式不是看完教程就结束，而是把它放进真实仓库里跑。

## 读陌生代码库

```text
请只读扫描这个仓库，输出：
1. 技术栈
2. 入口文件
3. 主要模块
4. 启动命令
5. 测试命令
6. 风险点
不要修改文件。
```

## 做新功能

好任务长这样：

- 目标明确。
- 文件范围清楚。
- 有验收方式。
- 能小步提交。

坏任务长这样：

- “帮我优化一下整个项目。”
- “随便重构。”
- “你看着办。”

## 修 Bug

我的修 Bug 流程：

1. 复现问题。
2. 找到最小原因。
3. 小范围修改。
4. 加测试或验证步骤。
5. 说明为什么不是别的问题。

## 前端 UI 验收

Codex 做前端时，不能只说“构建通过”。还要看：

- 390px 手机宽度是否溢出。
- 768px 平板是否拥挤。
- 1440px 桌面是否有层级。
- 图片和视频是否加载。
- CTA 是否被遮挡。

这也是我做 AI PickGold 网站时的验收方法。
