# 08. 把重复工作流沉淀成 Skills

Skills 的价值，是把你反复做的流程变成稳定方法。

我做 Codex 教程、开源仓库、封面、视频和发布包时，不希望每次都重新解释一遍规则。所以我会把稳定步骤写成 Skill 或固定提示词，让 Codex 每次按同一套流程执行。

## 什么任务适合做成 Skill

- 每周都会重复的资料整理、教程更新或发布包制作。
- 需要固定安全边界的部署、账号、密钥相关流程。
- 需要稳定输出格式的报告、清单、PR 描述和验收记录。
- 需要把技术内容转成公众号、小红书卡片、短视频脚本的内容流程。

## Skill 不是万能脚本

| 原则 | 说明 |
| --- | --- |
| 先写边界 | 明确哪些内容能公开，哪些只能内部使用 |
| 再写步骤 | 步骤要短、可执行、能被验证 |
| 最后写验收 | 让 Codex 知道什么时候该停、什么时候该交付 |

## 一个内容生产 Skill 的雏形

```text
请把这篇教程改写成：
1. 公众号大纲
2. 小红书卡片提纲
3. X 线程
4. 视频脚本
5. 人工审核清单

要求：
- 不自动发布
- 不暴露内部来源策略
- 保留事实核查点
- 最后给出适合公开的标题和封面方向
```

## 我的建议

不要一开始就追求复杂 Skill。先把你最常重复的 3 个流程写下来：

1. 项目接管流程。
2. 内容改写流程。
3. 发布前验收流程。

只要这 3 个跑顺，你的 Codex 工作流就会明显升级。
