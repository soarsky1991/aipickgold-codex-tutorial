# Cloud、GitHub 与 PR 工作流

Codex Cloud 适合把任务从“聊天窗口”推进到“仓库工作流”。但我不会把它当成无人值守替代品，它更像一个可以异步做事的工程助手。

## 什么任务适合 Cloud

- 根据 Issue 做一个小功能。
- 修复 CI 失败。
- 补 README、文档或测试。
- 做初步代码审查。
- 把重复工程任务做成 PR。

不适合：

- 需要生产密钥的任务。
- 需要访问私密客户数据的任务。
- 没有验收标准的大重构。
- 发布、支付、法律、投资等需要本人确认的动作。

## Issue 到 PR 的提示词

```text
请根据这个 Issue 先只读分析仓库，确认实现位置、风险和测试命令。
如果任务足够明确，再创建一个小范围改动。
PR 描述必须包含：问题、改动、验证、风险、后续建议。
```

## GitHub 自动化口径

我会把 GitHub 自动化拆成四层：

1. 读 Issue：理解任务，不急着写代码。
2. 改代码：只改和任务相关的文件。
3. 跑验证：测试、构建、lint、截图。
4. 写 PR：把证据和风险讲清楚。

## PR Review 清单

- 这个 PR 是否解决了 Issue？
- 是否修改了不相关文件？
- 是否泄露密钥、路径或内部策略？
- 是否跑过验证？
- 是否说明了未验证项？

Codex 可以帮你写 PR，但最终合并一定要有人看。
